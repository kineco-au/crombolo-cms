# 164 — The demo sites from seed files

**Epic:** Q — A site from the command line · **Priority:** should · **Size:** L
**Depends on:** 163

## Story

As someone reading a crombolo template to learn how a site is put together, I
want its content to be seed files I can open and change, so that the demo sites
show the way a real site is built rather than a script only this repository
has.

## Context

Every template's content is written by `scripts/build-template.ts`: one
TypeScript builder per site (`BASIC`, `STARTER`, `HARBOURSTONE`, `CROMBOLO`),
with fixed keys, run in a throwaway database and exported as each site's
committed bundle. The product site's docs section (story 157) is generated into
the same builder. Once seed files exist (story 163), the builders are a second,
private way of doing the same thing.

## Decisions (2026-10-25)

- **A demo site starts in three commands:**

  ```bash
  crombolo init --name "Harbourstone"                                    # a new, bare site
  crombolo bundle build sites/harbourstone --out ./harbourstone-bundle   # a bundle from the static directory
  crombolo start --bundle ./harbourstone-bundle --publish                # apply it and run
  ```

- **`crombolo bundle build [<dir>] [--template <id>] --out <dir>`** builds a
  bundle from a site directory, the current one by default.
  - **What it reads:** the directory's `schema/`, `components/`, `css/`,
    `scripts/` and `seed/` (content, Library and media).
  - **How it compiles:** the seed is compiled against that schema booted in a
    throwaway in-memory database, so no site or database of its own is
    needed.
  - **What it makes:** a bundle that installs into a bare site: types, views
    and content in one transaction, as the product site's bundle already
    does.
  - **Where the source comes from:** a path first; `--template <id>` names a
    demo shipped inside the CLI package (`demo/harbourstone`).
  - It sits under the existing `bundle` topic (beside `bundle purge`).
- **`content export` becomes `bundle export`**, kept for one release as a
  deprecated alias. It writes a bundle from a site's database, so it belongs
  beside `bundle build` (which writes one from a site directory). The `bundle`
  topic is then the compiled artifact (`export`, `build`, `purge`), and `seed`
  is the files a person edits (`check`, `apply`, `export`). `content import`
  and `content check` keep their names: they apply content to a site.
- **`seed build` goes**, kept for one release as a deprecated alias of
  `bundle build`. `seed check`, `seed apply` and `seed export` stay, as a
  site's day-to-day commands for its own seed.
- **Settled without an answer** (change here if not):
  - `crombolo init --template <id>` copies the demo's `seed/` with its schema
    and components, and the new site's start script is `crombolo start --seed
    --publish`. Templates stop shipping pre-built bundles, so the seed is the
    one source and an edit to it is applied on the next start.
  - The product site's generated docs pages are committed seed files under
    `sites/crombolo/seed/content/docs/`, each headed "generated: edit
    docs/<file>.md". A test fails when they are out of date.
- **Keys and ids:**
  - Node keys stay those of today's bundles, written as `key = "…"` in each
    seed file (the builders' keys are not path-derived).
  - A bundle's id is its content's, as story 163 made seeds' ids, so a changed
    demo re-applies on `start --bundle`, three ways, and an unchanged one does
    nothing.

## Findings (2026-10-25)

- **Where the content is today.** `scripts/build-template.ts` (1,177 lines)
  holds four builders (`BASIC`, `STARTER`, `HARBOURSTONE`, `CROMBOLO`).
  - **How they build:** `page`, `element` and `image` write through
    `DocumentRepository` into a throwaway site, which is exported with fixed
    bundle ids (`BUNDLE_IDS`) and a fixed provenance.
  - **Where the output goes:** 97 committed node files across
    `sites/*/bundles/`, plus `packages/cli/templates/basic`.
  - **The product site:** its bundle also carries its schema, components and
    styles (`CARRIES_SITE`). Its docs pages are generated by `docsTree` from
    `docs/*.md` and the CLI manifest (story 157).
- **The photographs** are in `assets/templates/harbourstone/`.
- **No alt text.** The Image media type has no alt property, so the
  photographs carry their names only. "With their alt text" needs an alt
  property on Image, which is not in this story; the sidecar's `name` is the
  nearest thing.
- **Elements sit at the top of the Library**, so story 163's unsupported
  Library folders are not needed.
- **`seed export`** writes pages only, with values mostly in stored shape. To
  turn the demos into seeds a person wants to read, it has to write Library
  elements and media too, and shorthand: rich text as `{ html }`, and paths
  for content, media and Library pickers and links, and block lists as tables.
- **Templates now:**
  - `crombolo init --template` copies `bundles/<slug>`, and the start script
    runs `crombolo start --bundle … --publish` (`packages/cli/src/templates.ts`,
    `sites/*/package.json`);
  - `stageTemplates` copies `sites/<x>` into the CLI package at pack time;
  - `basic` lives in `packages/cli/templates/basic`.

## Plan

1. **`seed export`, completed:**
   - Library elements (`seed/library/`) and media (`seed/media/`, the files
     copied out of the store, with sidecars for names and focal points);
   - shorthand wherever the compiler takes it back: rich text as `{ html }`,
     pickers and links as paths, and block lists and grids as `{ type,
     values, settings }`;
   - stored shape otherwise;
   - keys kept, and `order` written only where name order would differ.
   - `--all` exports the whole site.
2. **Migrate each demo.**
   - Build today's content with the old builder into a throwaway site.
   - Run `seed export --all` into `sites/<x>/seed/` (and
     `packages/cli/templates/basic/seed/`), then tidy the files by hand.
   - The photographs move into `seed/media/`.
   - A one-off comparison proves that the new `bundle build` of each site
     holds the same nodes, keys and values as its committed bundle.
3. **`bundle export`:** `packages/cli/src/commands/content/export.ts` moves
   to `commands/bundle/export.ts`, with `content:export` as a deprecated alias
   (as `bundle:install` is for `content import`). The docs, the product guide,
   `templates.ts` and the tests that name it move to the new name; a test
   holds that the old name still runs and says it is deprecated.
4. **`bundle build`** (`packages/cli/src/commands/bundle/build.ts`, with the
   work in `packages/server/src/bundle-build.ts`):
   - resolves the source: a path, or `--template <id>` from the staged
     templates;
   - boots a throwaway in-memory SQLite site from its `schema/` and
     `components/`;
   - runs `compileSeed`, then `siteSections` for schema, components, styles
     and scripts;
   - writes `writeBundle` and `writeBundlePackage`, named from the directory's
     `package.json`, or `--name`;
   - refuses with `seed check`'s findings, file and line, when the seed has
     problems;
   - registers `seed build` as a deprecated alias.
5. **The docs pages as seed files.** The docs build (`scripts/docs-site.ts`)
   writes `sites/crombolo/seed/content/docs/**.toml`, generated and headed so,
   with the keys `docsKey` gives them today. `bun run build:template` becomes:
   regenerate the docs seed, then run `bundle build` on `sites/crombolo` into
   its committed bundle. The builders, `BUNDLE_IDS` and the templates'
   committed bundles are removed.
6. **Templates:**
   - `init --template` copies `seed/` (media included) and writes
     `crombolo start --seed --publish` as the start script;
   - `templates.ts` loses its `bundle` field;
   - the `sites/*/package.json` start scripts move to `--seed`;
   - `stageTemplates` stages `seed/`.
7. **Tests:**
   - **The three commands, end to end** (`tests/integration/demo-from-bundle.integration.ts`):
     `init`, `bundle build sites/harbourstone`, then `start --bundle
     --publish`, serving the home page and a photograph; and the same with
     `--template demo/harbourstone`.
   - `bundle build` refuses a seed with problems, and its bundle installs
     into a bare site in one transaction.
   - `seed export --all` then `bundle build` round-trips a site's Library and
     media.
   - `tests/templates.test.ts`: every template has a seed that checks clean
     against its schema.
   - `tests/docs-site.test.ts`: the docs seed is current.
   - `new-site.integration.ts`: `init --template` then `start` serves the
     demo from its seed.
   - A site holding today's demo content imports the new bundle as unchanged.
8. **Docs:**
   - `seeds.md` (export of Library and media, and `bundle build`);
   - `bundles.md` and `content-transfer.md` (`bundle build`);
   - the product guide;
   - the CLI reference and the release notes;
   - `packaging-and-upgrades.md` (templates ship seeds, not bundles).

## What was built (2026-10-25)

- **`seed export`, completed** (`server/src/seed/export.ts`):
  - `--all` exports every page, every Library element, and every media item
    with its file;
  - rich text is written as `{ html }`, content pickers, media pickers,
    element pickers and links as paths, and block lists and grids as `{ type,
    key, values, settings }`;
  - the stored shape is written otherwise; keys are kept; `order` is always
    written;
  - long lists go one item per line.
- **The compiler, so a seed reproduces the demos exactly:**
  - a block may give its own `key` (and its settings' key);
  - media-picker keys use the builders' formula (`pickKey`);
  - `{ html }` rich text is taken as written, and only Markdown's links are
    rewritten;
  - an unnamed link stores `name: ''`;
  - `umbracoBytes` is a string, as an upload stores it;
  - media variants are not marked published;
  - the media type comes from the extension, a folder from a directory;
  - values carry their `references`.
- **`crombolo bundle build [<dir>] [--template <id>] --out`**
  (`server/src/bundle-build.ts`, `cli/src/commands/bundle/build.ts`):
  - boots the directory's schema in a throwaway SQLite database, links Folder
    as boot does, then runs `compileSeed` and `siteSections`;
  - the package is named from `site.json` or `package.json`, with
    `bundleIdFor` and a `>=` peer range;
  - `seed build` is its deprecated alias.
- **`crombolo bundle export`** is `content export` moved under `bundle`, with
  the old name as a deprecated alias.
- **`start --bundle` installs a bundle that carries sections** through
  `installBundleContent` (files staged, schema synced and content imported in
  one transaction), then boots the server again. Content-only bundles go the
  way they always have.
- **A fix found on the way:** `bootstrapDatabase` connected by `CROMBOLO_DB`
  rather than the configured dialect. A build whose config said `sqlite` would
  have opened a developer's Postgres. It now passes `config.dialect`.
- **The migration.** A one-off `--export-seed` run of the old builders exported
  each demo with `seed export --all` into:
  - `sites/{harbourstone,starter,crombolo}/seed/`;
  - `packages/cli/templates/basic/files/seed/`.

  A comparison of `bundle build` against each committed bundle found no
  difference in nodes, keys, parents, order, names or values for Basic,
  Starter and Harbourstone. The product site differed only in its four
  command-reference pages, which had changed since its bundle was last built.
  The photographs moved from `assets/templates/harbourstone/` into
  `seed/media/`.
- **The docs pages as seed files:** `writeDocsSeed` (`scripts/docs-site.ts`)
  writes `sites/crombolo/seed/content/home/docs/**`, each headed "Generated by
  `bun run build:template` from <source>: edit that, not this file". The Docs
  page and its Search page are hand-written.
- **`scripts/build-template.ts`** is now about 40 lines: regenerate the docs
  seed, then build the product site's bundle. The builders, `BUNDLE_IDS` and
  the template bundles (`sites/{harbourstone,starter}/bundles`,
  `packages/cli/templates/basic/bundle`) are removed.
- **Templates:**
  - `SiteTemplate.seed` replaces `bundle`;
  - a scaffolded site with a template starts with `crombolo start --seed
    --publish`;
  - `stageTemplate` copies `seed/` among the files and no bundle;
  - the sites' own start scripts and `bun run site` (`scripts/start-site.ts`)
    use `--seed`;
  - `init` says the seed is files to edit.
- **Tests:**
  - `tests/integration/demo-from-bundle.integration.ts`: the three commands
    from a path and from `--template`, serving the home page and a
    photograph, importing nothing on a second start, and a broken seed
    refused with its file and line;
  - `tests/seed.test.ts`: `--all` round-trips the Library and media into an
    identical build;
  - `tests/templates.test.ts`: every template's seed builds into a bundle
    that needs only its own types, and the demo's photographs travel byte for
    byte;
  - `tests/docs-site.test.ts`: the docs seed is current and says it is
    generated;
  - `tests/cli.test.ts`: `content export` still runs and points at `bundle
    export`;
  - `tests/sites.test.ts` and `tests/packaging.test.ts` (credits from
    `seed/media`), and the content-transfer integration test, moved to the new
    names.
- **Docs:**
  - `seeds.md` (a site in three commands, `export --all`, block keys, HTML as
    written);
  - the product guide;
  - `bundles.md`, `content-transfer.md`, `configuration.md` and `testing.md`;
  - the README and the Harbourstone credits;
  - the release notes.
- **Test runs:**
  - SQLite 2804 pass and Postgres 2802 pass. The three failures on each were
    tests still describing bundles: two for `bun run site`, now `--seed`, and
    the old `seed build` test, now `bundle build`'s alias. They pass.
  - Integration: four suites started scaffolded sites with `--bundle
    bundles/<template>` and now use `--seed`, and the new-site media check
    reads the seed's photograph. All pass, with one `test.todo` (story 180).
- **Not done:**
  - **Alt text:** the Image type has no alt property.
  - **Production:** a bare site's `1.0.0` schema becoming the demo's without
    a version bump is refused, so the three commands are for development, or
    for a bumped version.
  - **Library file names** come from the elements' names, which are long for
    tasting notes. They are free to rename, since each file carries its key.
