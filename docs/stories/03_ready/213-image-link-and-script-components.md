# 213 — Image, Link and Script components

**Epic:** O — Building a site · **Priority:** should · **Size:** M
**Depends on:** 199

## Story

As a developer used to `next/image`, `next/link` and `next/script`, I want
the same components in Crombolo's templates. Then responsive images, links
to content and third-party scripts are done right by default rather than
written by hand on every page.

## Context

Crombolo's image pipeline already resizes, crops and converts on the fly
(`packages/server/src/imaging.ts`), and `cropUrl()` writes its URLs (199 adds
Umbraco's full options). But every template writes its own `<img>`, with its
own `srcset`, sizes and lazy loading, or forgets to. Links to content are
written by hand from `content.url`, and third-party scripts are raw `<script>`
tags.

Next.js gives:
- **`<Image>`:** responsive `srcset`, `sizes`, lazy loading, width and
  height against layout shift, a blur placeholder, and priority for the
  largest image on the page.
- **`<Link>`:** prefetching.
- **`<Script strategy>`:** `afterInteractive`, `lazyOnload` and the like.

## Decisions before implementation

- **`<Link>` without a client router.** Crombolo pages are full page loads.
  Recommended: `<Link>` renders an `<a>`, takes `href` or a content item,
  marks the current page with `aria-current`, and prefetches on hover through
  `<link rel="prefetch">`. There is no client-side navigation. A client router
  is out of scope.
- **Blur placeholders.** Recommended: a tiny LQIP generated by the image
  pipeline and cached with the variant, inlined as a data URL.

## Acceptance criteria

- [ ] `<Image>` from `@crombolo/crombolo` takes a media item, an image cropper
      value or a URL, with `width`, `height`, `sizes`, `fill`, `quality`,
      `priority`, `placeholder="blur"` and a crop name or focal point. It
      writes `srcset` across the site's configured widths through the imaging
      pipeline, `loading="lazy"` unless `priority`, `decoding="async"`, and the
      intrinsic size.
- [ ] `priority` also adds a `<link rel="preload" as="image">` to the head.
- [ ] Protected media renders through its protected URL, with no public
      variant.
- [ ] `<Link href>` or `<Link content>` renders an `<a>` with the content's
      URL in the request's culture, `aria-current="page"` on the current page,
      and hover prefetch unless `prefetch={false}`.
- [ ] `<Script src strategy>` supports `beforeInteractive`,
      `afterInteractive` (the default) and `lazyOnload`, deduplicated per page,
      with the page's CSP nonce.
- [ ] `docs/writing-components.md` describes all three, mapped to Next.js's.
      Unit tests cover `srcset` and sizes, placeholders, preload, protected
      media, the current-page marker and script strategies.
