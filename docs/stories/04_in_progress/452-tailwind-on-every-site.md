# 452 — Tailwind on every site

**Epic:** O — Building a site · **Priority:** should · **Size:** L
**Depends on:** 260, 337

## Story

As a developer building a site, or an agent working on one, I want to style its views,
partials and components with Tailwind's classes and nothing else, with no build step or
import, so that a class I write in a view works on the page at once, in development and
in production, and the editor I write it in suggests the classes there are.

## Context

A site styles its pages with its own CSS in `css/`, linked through `asset()` (`260`),
which serves it hashed and cached for a year. Tailwind needs no import, since its
classes are just class names. What a site would need is the CSS generated for the
classes its views use, and a link to it on every page.

Views and partials can be edited in the back office's template editor (`337`), so a new
class can appear without a deploy. The CSS can't come only from a build step.

## Decided (2026-11-28)

1. **On for every site**, Tailwind's base reset (preflight) included. A site that doesn't
   want it turns it off.
2. **Generated by the server**, at boot, on every save in the template editor, and in
   the dev server's watch mode, not by a build step.
3. **No native binaries.** Tailwind's JavaScript compiler, with the CMS scanning the
   site's files for class names, so the container image and the Windows host need
   nothing new.
4. **Completion in the template editor,** in this story rather than one of its own: classes
   suggested as you type, with their CSS, colour swatches and hover.

## The design

- **What is scanned:** the site's views, partials and components (`.tsx`, `.ts`, `.jsx`,
  `.js`, `.html`), as the server finds them, including those saved in the back office.
  Any token that could be a class (Tailwind's own candidate rules) is a candidate; the
  compiler keeps the ones that are classes.
- **The input:** Tailwind's default (`@import "tailwindcss"`). A site's own
  `css/tailwind.css`, when there is one, replaces it, for `@theme`, plugins,
  `@source` for extra files, and `@source inline(…)` for classes used only in content.
- **The output:** served at `/css/tailwind.css` through `asset()`, hashed and kept for a
  year. A new class saved makes a new hash, and pages link the new one. Every server
  builds the same file from the same sources, so nodes agree without telling each other.
- **The link:** added to every page's `<head>` by the renderer, before the site's own
  stylesheets, so the site's rules win where both set something. A view that links it
  itself isn't given a second link.
- **Turning it off:** `styles: { tailwind: false }` in `crombolo.config.ts` (and
  `CROMBOLO_STYLES_TAILWIND=false`). Nothing is generated or linked.
- **Classes in content:** classes typed into rich text or pasted HTML are in no file, so
  they're not generated unless the site names them with `@source inline(…)`. The docs
  say so.
- **Errors:** a site's `css/tailwind.css` that doesn't compile is logged with its line,
  and the last good stylesheet stays served. In development the live-reload banner shows
  the error.
- **The scaffold and the demo:** `crombolo new` sites and the demo use Tailwind classes
  in at least one view, so a new site shows it working. New sites get a
  `css/tailwind.css` holding `@import "tailwindcss";`, so Tailwind's own IntelliSense
  extension switches on in a local editor (VS Code, Cursor) for developers and agents.
- **Completion in the template editor:**
  - **The class list:** the server answers, at a back-office route, every class the
    site's Tailwind knows (its own `@theme` included), each with the CSS it makes and,
    for a colour, the colour, plus the variants (`hover:`, `md:`, `dark:` and the rest).
    Read once per editor; a change to `css/tailwind.css` changes it.
  - **Where it completes:** inside `className="…"`, `class="…"`, and template strings or
    `clsx`/`cn` calls given to them, in views, partials and components. Monaco offers
    the classes matching what is typed, variants combining with them, each with its CSS
    and a swatch for a colour.
  - **Hover:** a class shows the CSS it makes. A class Tailwind doesn't know isn't
    marked as an error, since it may be the site's own.
  - **How:** a completion and a hover provider registered on Monaco by `tsx-editors.js`,
    through the fork's `viewEditor` seam it already uses; no change to the fork.

## Acceptance criteria

- [ ] **A class in a view** is styled on the page with no import or build, in
      development and in production.
- [ ] **A class saved in the template editor** is styled on the next page load; the
      stylesheet's hash changes and pages link the new one.
- [ ] **`css/tailwind.css`** replaces the default input: a `@theme` colour is usable as a
      class, and `@source inline(…)` generates classes used only in content.
- [ ] **The link** is in every page's head before the site's own CSS, once.
- [ ] **`styles.tailwind: false`** generates and links nothing, and the editor offers no
      classes.
- [ ] **The template editor completes classes** inside `className`/`class` strings and
      `clsx`/`cn` calls: matching classes with their CSS, variants combined, a swatch for
      a colour, the site's own `@theme` included; hovering a class shows its CSS.
- [ ] **A new site has `css/tailwind.css`**, so Tailwind's IntelliSense works in a local
      editor.
- [ ] **A broken `css/tailwind.css`** is logged with its line and the last good
      stylesheet stays served.
- [ ] **No native binaries:** the container image and the Windows host job build and
      pass unchanged.
- [ ] **Tests:** scanning, compiling, the link, the setting, a save regenerating, two
      servers giving the same hash, and the error; the class list's route and what the
      completion offers where (a pure function of the text and cursor); browser
      journeys: a class saved in a view styles the page, and typing in `className`
      offers a class that is then inserted.
- [ ] **Docs:** `docs/rendering.md` (styling with Tailwind), `docs/configuration.md`,
      the settings reference, and the release notes. The upgrade notes warn that
      Tailwind's base reset may change an existing site's headings, margins and lists,
      and say how to turn it off.

## Out of scope

- Tailwind in the back office, which has its own styles.
- A Tailwind version a site chooses: the CMS ships one and upgrades it in its releases.
